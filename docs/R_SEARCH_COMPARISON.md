# ART and R-Search experimental comparability

Use the [benchmark reference](R_SEARCH_BENCHMARK_REFERENCE.md) for published numbers. Appendix A.1 reports 500 examples each for HotpotQA, 2Wiki and MuSiQue from the Trivedi et al. splits, all 125 FlashRAG Bamboogle examples, and random samples of 500 from each FlashRAG single-hop test set. Table 2 contains separate Qwen2.5-3B-Instruct and 7B results. [R-Search paper, arXiv v1](https://arxiv.org/html/2506.04185v1)

| Dimension | R-Search published setup | ART source and artifacts | Comparability |
|---|---|---|---|
| Generator | Qwen2.5-3B-Instruct and 7B-Instruct policies | REVIVE derived from the 3B Instruct backbone | Same starting family and scale for the 3B row. Different learned checkpoint and model architecture. |
| Training | Multi-reward RL, with GRPO in Table 2, on 2WikiMultiHopQA | MuSiQue teacher continuations, attention mixing and retrieval-score regularization | Different objective and data. In-domain status differs for MuSiQue and 2Wiki. |
| Evaluation sets | HotpotQA, 2Wiki, MuSiQue and Bamboogle, plus NQ, TriviaQA and PopQA | Loaders use R-Search-distributed evaluation files for the first three. All archived ART rows report 500 examples. | Shared dataset names, upstream distribution and sample count for the overlap. Exact file revisions, ID order and identity with paper samples are unverified. No archived ART numbers for the four other benchmarks. |
| Dense encoder and k | E5, with e5-base-v2 identified by the official repository. Top-5 evaluation and top-3 training. | E5-base-v2 builders and dataset-specific adapters. Top-5 script sets 5 and model default is 3. | Encoder and top-5 configuration match at the named-setting level. Document formatting, actual index revisions, passage limits and search budgets can differ. |
| Retrieval corpus | Dataset-specific Wikipedia corpora for the three overlapping tasks | ART builds its own indices. HotpotQA and 2Wiki corpus scripts ingest R-Search inputs. A saved MuSiQue comparison CSV reports matching SHA-256 digests for all six raw split files across original and R-Search distributions. | The saved hashes apply to raw split files. The final index, ranking and identity of the paper's evaluation sample remain unverified. |
| Search prompt | Policy emits a query inside search tags and synthesizes an explicit evidence block before answering. Retrieved passages use observation tags. | ART's pure prompt delegates search timing to the system. The score triggers retrieval and the query comes from reasoning text. The prompt uses observation and answer tags. | Shared broad answer and observation convention, different trigger, query construction and evidence instructions. |
| Scoring | Published answer EM and F1 | Alias-max normalized EM and token F1, plus a substring Acc and tag-coverage count | EM/F1 are common metric families. Verify exact normalization, extraction and malformed-output handling before claiming parity. Acc is ART-specific in these tables. |
| Decoding and resources | vLLM evaluation, inference temperature 0.1 (Appendix A.3), and the training settings in the benchmark reference | Current top-5 code uses Transformers generation and temperature 0.1. Historical runtime and exact remote revisions are unverified. | Temperature matches at the documented setting level. Seed, token budgets, search stop rules and runtime parity remain unverified. |

The published 3B R-Search EM/F1 values are 43.4/54.4 for HotpotQA, 65.0/72.6 for 2Wiki and 25.8/34.8 for MuSiQue. Keep them in an external benchmark table with the original citation. The author-confirmed matching configuration applies to paired ART demo runs. A cross-paper comparison remains descriptive because training data, policy objectives, prompting and retrieval mechanics differ, and the archived configurations do not establish evaluation parity.
